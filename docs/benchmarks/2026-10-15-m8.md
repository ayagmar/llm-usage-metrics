## M8 A/B benchmark (2026-10-15)

`scripts/benchmark-baseline.mjs` at the M8 head (with the `statusline-aged` scenario), run
against three builds of the CLI:

| Build  | Git       | What it is                                          |
| ------ | --------- | --------------------------------------------------- |
| M0     | `78feb74` | the build of `2026-10-14-baseline.md`               |
| pre-M8 | `abe3ace` | `core/integration` after M0–M7                      |
| M8     | `d2de9a0` | `core/m8` with the summary, worker and read changes |

Each old build was checked out in its own worktree with
`pnpm install --frozen-lockfile && pnpm run build`, and the same script file was copied in,
so every build ran the same corpus and commands.

### Corpus

- Synthetic pi and codex sessions, 200000 lines per source over 4 files each: 399984
  events, 140 daily periods, 193590905 total tokens. All three builds reported the same
  totals.
- `statusline-aged` uses a second corpus with the same line counts, where 3 of the 4 files
  per source have their events and mtime 60 weeks old.
- 5 timed runs per scenario per round. Max RSS method: python-rusage.

### Method

- 3 serial rounds, alternating order: M0, pre-M8, M8; then M8, pre-M8, M0; then M0,
  pre-M8, M8. One build ran at a time. Each round regenerated the corpus.
- The figure of record is the minimum wall time over all 15 timed runs (3 rounds × 5) per
  build and scenario. RSS is the range of the 3 per-round values.
- Load average (1 min) at the start of each build's run: 2.2 to 5.5. No run started above 8.

| Round | Order          | Load at each start |

| 1     | M0, pre-M8, M8 | 4.16, 5.50, 4.15   |
| 2     | M8, pre-M8, M0 | 2.98, 2.87, 2.22   |
| 3     | M0, pre-M8, M8 | 2.97, 4.60, 3.14   |

### Reading it

- The statusline tick gains the most: one third off on the full corpus and a quarter off
  when most files are outside its window. The warm `daily` run gains about a sixth.
- `cold` (store off) is 4% faster than pre-M8 but still 4% slower than M0 in all three
  rounds; the cold regression from M1–M7 is narrowed, not closed. Each source in
  this corpus is below the 256 MiB parse-worker threshold and it has no Claude logs, so
  M8's Claude and pi worker change does not show here.
- `statusline-aged` is faster than `statusline` on every build, M0 included: the skip of
  files older than the window predates M8.
