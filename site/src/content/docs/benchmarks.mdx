This page publishes measured absolute runtimes for `llm-usage` on real local data, with `ccusage` numbers included as context. There are no cherry-picked speedup claims here: `ccusage` 20.x is a native Rust binary, it wins cold runs, and this page says so. All numbers were measured on 2026-07-09 with 5 timed runs per cell.

## Results

### codex — `daily` (5 runs each)

| Tool                                               | Cache | Median (s) | Mean (s) | Min (s) | Max (s) |
| -------------------------------------------------- | ----- | ---------: | -------: | ------: | ------: |
| `ccusage codex daily`                              | cold  |      0.516 |    0.515 |   0.487 |   0.549 |
| `ccusage codex daily --offline`                    | warm  |      0.292 |    0.292 |   0.281 |   0.306 |
| `llm-usage daily --source codex`                   | cold  |      1.655 |    1.670 |   1.642 |   1.715 |
| `llm-usage daily --source codex --pricing-offline` | warm  |      0.996 |    1.005 |   0.971 |   1.046 |

Derived from median runtime: llm-usage vs ccusage cold `0.31x` (ccusage ~3.2x faster), warm `0.29x` (ccusage ~3.4x faster).

### claude — `daily` (5 runs each)

| Tool                                                | Cache | Median (s) | Mean (s) | Min (s) | Max (s) |
| --------------------------------------------------- | ----- | ---------: | -------: | ------: | ------: |
| `ccusage claude daily`                              | cold  |      0.335 |    0.354 |   0.317 |   0.437 |
| `ccusage claude daily --offline`                    | warm  |      0.478 |    0.474 |   0.464 |   0.483 |
| `llm-usage daily --source claude`                   | cold  |      0.883 |    0.896 |   0.833 |   1.010 |
| `llm-usage daily --source claude --pricing-offline` | warm  |      0.256 |    0.255 |   0.227 |   0.287 |

Derived from median runtime: llm-usage vs ccusage cold `0.38x` (ccusage ~2.6x faster), warm `1.87x` (llm-usage ~1.9x faster).

## Where each tool wins

- **Cold runs favor ccusage.** ccusage 20.x is a native Rust binary; llm-usage is TypeScript on Node. Cold runs are dominated by JSONL parsing, where native code wins: llm-usage parses the 1.8 GiB codex corpus cold in ~1.65 s (buffer reader + byte prefilters + a worker-thread parse pool), which is fast for a Node tool but ~3x behind the Rust binary.
- **Warm claude favors llm-usage (~1.9x).** The SQLite event store serves already-parsed events, so llm-usage skips file parsing entirely and returns in ~0.26 s, while ccusage re-reads the corpus every run (~0.48 s).
- **Warm codex does not flip.** The store skips parsing, but the warm path still materializes and aggregates every stored codex event in JS, and the codex ledger holds far more events than the claude one. That aggregation cost (~1.0 s) is the current warm-path bottleneck.

## Dataset scope

| Corpus | Files                                    | Size on disk |
| ------ | ---------------------------------------- | ------------ |

## Methodology

- 5 timed runs per cell, on an otherwise-quiet machine (load average 1.30 / 22 logical CPUs before the run).
- Cold cells use a fresh `XDG_CACHE_HOME` and `LLM_USAGE_EVENT_STORE=0`.
- Each tool's warm cache is populated by one live warm-up run, then timed warm cells run offline (`--offline` for ccusage, `--pricing-offline` for llm-usage).
- Asymmetry to disclose: llm-usage runs get `LLM_USAGE_SKIP_UPDATE_CHECK=1`; ccusage exposes no equivalent knob, so none is applied.

## Engineering notes: the cold-codex path

Before the parse-pipeline work, a cold codex run over this corpus took 8.7 s; it takes 1.65 s now. The mechanisms, in pipeline order:

1. Byte prefilters and a buffer-based JSONL reader (`src/utils/read-jsonl-objects.ts`) skip irrelevant lines before any JSON parsing.
2. A per-timezone local-date window cache for period bucketing (`src/utils/time-buckets.ts`) avoids repeated date math per event.
3. An event-store warm read fast path serves already-parsed events from SQLite.
4. A worker-thread parse pool (`src/cli/parse-worker-pool.ts`) parses large JSONL files in parallel.

## Reproduce it

```bash
pnpm run build
npx -y ccusage@latest --version
CCUSAGE_BIN=$(find ~/.npm/_npx -name ccusage -path '*/.bin/*' | head -1)
node scripts/perf-production-benchmark.mjs --runs 5 --scenario codex --ccusage-bin "$CCUSAGE_BIN"
node scripts/perf-production-benchmark.mjs --runs 5 --scenario claude --ccusage-bin "$CCUSAGE_BIN"
```

The script also accepts `--json-output <path>` and `--markdown-output <path>` to export artifacts. Results are machine- and dataset-specific: re-run on your own workload before drawing conclusions.
