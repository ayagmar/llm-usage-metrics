`llm-usage compare` summarizes two windows with the same source, provider, model, timezone, history, and pricing settings. It reports the current value, baseline value, absolute delta, and percentage change for each metric.

## Default comparison

```bash
llm-usage compare
```

With no date flags, the current window is the current local month to date and the baseline is the same days of the previous month (clamped to that month's last day), so a partial month is never compared against a full one. On 6 October the report compares 1–6 October with 1–6 September. The report timezone decides those boundaries.

## Compare a chosen range

```bash
llm-usage compare \
  --since 2026-06-01 \
  --until 2026-06-30
```

An explicit current range needs both `--since` and `--until`. Without baseline flags, the CLI chooses the equal-length window immediately before the current range.

The equal-length rule uses the number of days. A 31-day March range therefore compares with the 31 days ending on the last day of February, rather than with February alone.

## Set both windows

```bash
llm-usage compare \
  --since 2026-06-01 \
  --until 2026-06-30 \
  --vs-since 2026-04-01 \
  --vs-until 2026-04-30
```

`--vs-since` and `--vs-until` must appear together. The two ranges may have different lengths, so check active days before interpreting a raw total change.

## Metrics

The totals section compares:

- all five token buckets and total tokens
- cost
- event count
- active days

The source section compares cost by source. Cost keeps the shared pricing semantics: a tilde marks an incomplete amount, and a missing cost stays unresolved.

A percentage delta is unavailable when the baseline value is zero and the current value is nonzero. Both zero values produce a `0%` change.

## Filter both windows

```bash
llm-usage compare --source codex --model codex
llm-usage compare --provider anthropic --no-history
```

Filters apply once to the combined dataset before the command separates events into the current and baseline windows. This keeps the scope consistent. `--repo` keeps some [projects](/llm-usage-metrics/projects/) only, and `--machine` some [machines](/llm-usage-metrics/machines/).

## Compare each project

```bash
llm-usage compare --by-repo
```

`--by-repo` adds a **By project (cost)** table under the source table: each project's cost in both windows, the delta, and the percentage change, ordered by the size of the change. A project keeps one label in both windows. In `--json`, the rows are under `data.projects`, each with `repoRoot`, `project`, and `current`, `baseline`, `delta`, and `deltaRatio` totals.

The table shows the 20 projects whose cost changed most (then whose tokens changed most), then one `N other projects` row with the rest; a note on `stderr` says so. `--top N` shows N projects, and `--top 0` shows them all. The limit applies to `--json` as well: the last row has `otherProjects`, the number of projects it holds, and no `repoRoot`.

## Export

```bash
llm-usage compare --json
llm-usage compare --markdown
```

Compare supports terminal, JSON, Markdown, and `--share`. The [interactive report](/llm-usage-metrics/share/) `compare-share.html` holds both windows, opens on the current one, and shows the comparison as a panel. Diagnostics stay on `stderr` in every format.

```bash
llm-usage compare --share --no-open
```
