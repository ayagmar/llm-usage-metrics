---
title: Multiple machines
description: Combine usage from your laptop, desktop, and servers into one report over ssh.
---

If you use coding agents on several machines, one machine's reports can include the others. Each machine keeps parsing its own logs; this machine fetches what they count over ssh and keeps a copy, so reports work offline and stay fast.

## Quick start

1. Install llm-usage-metrics on both machines.
2. Check that `ssh laptop` logs in without asking for a password.
3. On this machine:

```bash
llm-usage machine add laptop
llm-usage            # every report now includes the laptop
```

## Set up

`machine add` takes a name and an ssh destination. The name is how reports refer to the machine: 1-32 lowercase letters, digits, or dashes. The destination is anything `ssh` accepts: `host`, `user@host`, or a `Host` alias from `~/.ssh/config`, whose settings (port, key, `ProxyJump`, `ControlMaster`) all apply. Without a destination, the name is used as one, which suits an ssh alias or a host name:

```bash
llm-usage machine add laptop                    # ssh laptop
llm-usage machine add work me@10.0.0.5          # a name of your choice for another destination
```

ssh must log in without a password prompt: key login, or a key loaded in `ssh-agent`.

`machine add` fetches the machine's usage once and only then adds it to your [config file](/llm-usage-metrics/configuration/), keeping your comments:

```toml
[machines.laptop]
ssh = "laptop"
```

The first fetch can take a minute: the other machine parses all its logs, as its own first report would.

If node comes from a version manager (nvm, fnm, volta, mise), a non-interactive ssh command usually cannot find `llm-usage`. `machine add` then asks the machine's login shell where it is and saves a `command` that puts that directory on `PATH`. To set it yourself:

```bash
llm-usage machine add vps --command "/home/me/.local/bin/llm-usage"
```

## Use it

Every report includes the machines you added. When a machine's usage was last fetched more than 10 minutes ago, the report fetches it again while it parses this machine's logs, waiting at most 30 seconds. A machine that is off or unreachable does not stop the report: it uses the usage fetched last time and says so, and waits 10 minutes before trying again.

```bash
llm-usage daily               # this machine and the others, fetched when due
llm-usage daily --no-sync     # use what was fetched last, without connecting
llm-usage sync                # fetch every machine now
```

The `stderr` summary says which machines a report includes and when each was last fetched:

```text
ℹ Machines: laptop (synced 4 min ago); left out 1,204 event(s) already counted.
```

`--machine` limits a report to some machines; `local` is this one:

```bash
llm-usage monthly --machine laptop
llm-usage monthly --machine local,vps
```

Reports combine every machine into the same rows. To see each machine apart, `--by-machine` splits each source row of `daily`, `weekly` and `monthly` by machine, and `events` names the machine of each event from another machine:

```bash
llm-usage monthly --by-machine     # claude (local), claude (laptop), ...
```

Until you add a machine, every row is `(local)`. The share card (`--share`) always combines machines.

A report pointed at a custom directory (`--claude-dir`, `--source-dir`) counts only that directory, without other machines, unless you name them with `--machine`. `statusline` includes other machines too, from their last fetch; it never connects to them, so a status bar stays fast.

## How it works

- `llm-usage sync` runs `llm-usage machine export` on each machine over ssh. The machine refreshes its own [event store](/llm-usage-metrics/caching/) and sends only the files that changed since the last fetch, in a [versioned format](/llm-usage-metrics/output-formats/#machine-export).
- What it sends is what that machine's own reports count, history included, for the sources its own config selects. Costs are calculated here, with this machine's pricing.
- Each machine's usage is kept in its own file, `machines/<name>.db`, next to this machine's event store; your own ledger never mixes with it. A failed fetch keeps the previous copy, and `machine list` shows the error.
- The same session can reach several machines (a copied `~/.claude`, a synced or shared home directory). An event already counted, from this machine or one added before, is counted once. A session continued on another machine keeps its new turns. This relies on both machines parsing logs the same way, so the `Machines:` note warns when another machine runs a different llm-usage-metrics version.
- Repository paths are those of the machine the usage came from: `efficiency --repo-dir` and `session --by-repo` treat the same repository at another path as a different one.

## Manage machines

```bash
llm-usage machine list            # each machine, when it last synced, how much is cached
llm-usage sync laptop --full      # fetch every file again
llm-usage machine remove laptop   # delete its config table and its cached usage
```

`llm-usage doctor` shows the same machines next to your sources, from what is cached; it never connects to them.

To stop fetching a machine but keep its cached usage in reports, set `enabled = false` in its table.

## Troubleshooting

`sync` and `machine add` print what failed and how to fix it:

| Message                                 | Fix                                                                                                                               |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `ssh could not log in without a prompt` | Set up key login (`ssh-copy-id laptop`) or load your key into `ssh-agent`. Syncs never prompt.                                    |
| `ssh does not know this host yet`       | Connect once with `ssh laptop` to check and accept its host key.                                                                  |
| `llm-usage was not found`               | Install llm-usage-metrics there, or set `command` to how it starts (see [Set up](#set-up)).                                       |
| `too old to export usage`               | Update llm-usage-metrics on that machine.                                                                                         |
| `no complete export within 30s`         | The machine needs longer than a report waits (a large first parse); run `llm-usage sync <name>`, which waits as long as it takes. |
| `the export ended early`                | The connection dropped or the other machine stopped; run `llm-usage sync` again. Nothing was changed.                             |

After a node upgrade, a saved `command` with a version in its path may stop working; remove the machine and add it again to detect the new path.
