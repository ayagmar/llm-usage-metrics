The CLI keeps report data on `stdout` and diagnostics on `stderr`. Redirecting JSON or Markdown therefore produces a clean data file while discovery and pricing notes remain visible in the terminal.

## Choose a format

| Report                   | Terminal | JSON | Markdown | Share card                  |
| ------------------------ | -------- | ---- | -------- | --------------------------- |
| Summary                  | Yes      | Yes  | Yes      | Yes                         |
| Daily / weekly / monthly | Yes      | Yes  | Yes      | Yes                         |
| Compare                  | Yes      | Yes  | Yes      | Yes                         |
| Session                  | Yes      | Yes  | Yes      | No                          |
| Trends                   | Yes      | Yes  | Yes      | Combined view only          |
| Efficiency               | Yes      | Yes  | Yes      | Monthly, combined view only |
| Optimize                 | Yes      | Yes  | Yes      | Monthly only                |
| Wrapped                  | Yes      | Yes  | Yes      | Yes                         |
| Doctor / prune           | Yes      | Yes  | No       | No                          |

[Events](/llm-usage-metrics/events/) exports JSONL or CSV using `--format`; it does not use the report-format flags. `schema` prints a JSON Schema document, and `config` emits text.

## Terminal

```bash
llm-usage daily
```

The default renderer uses a boxed title and a Unicode table. `NO_COLOR=1` removes ANSI color without changing the content.

Usage tables fit the terminal width. When the full table is too wide, the renderer steps down in this order until it fits: abbreviate token counts (`616M`, `24.3K`; cost stays exact), hide Reasoning and Cache Write, hide Models, then hide Input and Output. At any step, a model name longer than the space left for the Models column (at least 20 characters) gets a middle `…` instead of wrapping. Period, Source, Cache Read, Total, and Cost always stay. A note on `stderr` lists what was left out. Piped output has no terminal width and keeps every column.

```bash
llm-usage daily --compact
```

`--compact` starts from the abbreviated table without Reasoning and Cache Write, even when the terminal is wide or the output is piped. It works with terminal and Markdown output, not JSON. If even the narrowest table is wider than the terminal, an overflow warning goes to `stderr`; use a wider terminal or JSON.

## JSON

```bash
llm-usage daily --all --json > usage.json
```

Use JSON for scripts and pipelines. Without date bounds, `daily` and `weekly` cover only their default windows (the last 7 days and the last 8 weeks), so scripts that need full history should pass `--all` or explicit `--since`/`--until` dates. Every report wraps its payload in a versioned envelope:

```json
{
  "schemaVersion": 1,
  "report": "usage",
  "data": []
}
```

`report` identifies the report family (`summary`, `usage`, `session`, `trends`, `compare`, `efficiency`, `optimize`, `wrapped`, `doctor`, or `prune`) and `data` carries the report-specific payload documented on each report page. `schemaVersion` increments only on breaking JSON changes; additive fields inside `data` are safe and do not bump it. Diagnostics never enter the JSON body. The envelope arrived in 0.8.0 — [Migrating to 0.8](/llm-usage-metrics/migrating-to-0-8/) maps the old field names to the new ones.

Every payload has a published JSON Schema (draft 2020-12) validated in CI against real CLI output:

The installed CLI also carries these schemas, so pipelines can validate against the exact contract of their installed version without the network:

```bash
llm-usage schema usage > report-usage.schema.json
llm-usage schema --list
```

`schema` accepts every report name plus `events-line` and `config`, and prints the schema document itself (not wrapped in the report envelope). Report and `events-line` schemas embed the shared definitions under `$defs`, so the printed file compiles on its own in any JSON Schema 2020-12 validator.

## Markdown

```bash
llm-usage daily --markdown > usage.md
```

Markdown works for summary, usage, compare, session, efficiency, optimize, trends, and wrapped reports. It does not work for doctor, prune, or events.

Usage and session output keep the same ordering and row limits as the terminal renderer. `--per-model-columns` and `--compact` also work with Markdown usage reports.

## Share cards

`--share` writes a 1200×630 card, the usual size for social link previews, to the current directory as two files:

- an SVG in the dark theme
- an HTML page with the same name that shows the card in dark and light, with **Download PNG** and **Copy image** buttons

The page opens in your default browser; add `--no-open` to only write the files (useful over SSH or in scripts). The page works offline: it renders the PNG in the browser at twice the card size, loads nothing from the network, and needs no extra software. Copying an image needs a browser that supports image clipboard writes; Download PNG works everywhere. The command still prints the normal report to `stdout`.

| Report     | Command                                                        | File                           |
| ---------- | -------------------------------------------------------------- | ------------------------------ |
| Summary    | `llm-usage summary --share`                                    | `summary-share.svg`            |
| Usage      | `llm-usage monthly --share`                                    | `usage-monthly-share.svg`      |
| Compare    | `llm-usage compare --share`                                    | `compare-share.svg`            |
| Trends     | `llm-usage trends --share`                                     | `trends-share.svg`             |
| Wrapped    | `llm-usage wrapped --year 2026 --share`                        | `llm-usage-wrapped-2026.svg`   |
| Efficiency | `llm-usage efficiency monthly --share`                         | `efficiency-monthly-share.svg` |
| Optimize   | `llm-usage optimize monthly --candidate-model gpt-4.1 --share` | `optimize-monthly-share.svg`   |

Each HTML page takes the SVG's name with `.html`. The summary card leads with your current streak above the past year's activity heatmap. Usage share works for daily, weekly, and monthly reports, and folds sources past the sixth into one entry. Efficiency share shows the last 12 months and optimize share the top 5 candidates over the last 8 months; the full data stays in the report. Efficiency and optimize share work for monthly reports only. Trends share requires the combined view, so it cannot be paired with `--by-source`. Efficiency share cannot be paired with `--by-source` either.

Session, doctor, prune, and events do not support `--share`.

## Per-model columns

```bash
llm-usage monthly --per-model-columns
llm-usage monthly --markdown --per-model-columns
```

This usage-report option expands token and cost values per model into aligned multiline cells. Models are ranked by total tokens inside each row.

## Keep diagnostics separate

```bash
llm-usage daily --all --json > usage.json 2> usage.log
```

`usage.json` contains report data. `usage.log` contains a one-line discovery and pricing summary, any warnings, and notes such as `--history` totals. Pass `--quiet` to keep only warnings, or `--verbose` to add per-source counts, routine skipped rows, and the config and env blocks.
