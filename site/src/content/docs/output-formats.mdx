The CLI keeps report data on `stdout` and diagnostics on `stderr`. Redirecting JSON or Markdown therefore produces a clean data file while discovery and pricing notes remain visible in the terminal.

## Choose a format

| Report                   | Terminal | JSON | Markdown | Share report |
| ------------------------ | -------- | ---- | -------- | ------------ |
| Summary                  | Yes      | Yes  | Yes      | Yes          |
| Daily / weekly / monthly | Yes      | Yes  | Yes      | Yes          |
| Compare                  | Yes      | Yes  | Yes      | Yes          |
| Session                  | Yes      | Yes  | Yes      | No           |
| Trends                   | Yes      | Yes  | Yes      | Yes          |
| Efficiency               | Yes      | Yes  | Yes      | Yes          |
| Optimize                 | Yes      | Yes  | Yes      | Yes          |
| Wrapped                  | Yes      | Yes  | Yes      | Yes          |
| Doctor / prune           | Yes      | Yes  | No       | No           |

[Events](/llm-usage-metrics/events/) exports JSONL or CSV using `--format`; it does not use the report-format flags. `schema` prints a JSON Schema document, and `config` emits text.

## Terminal

```bash
llm-usage daily
```

The default renderer uses a boxed title and a Unicode table. `NO_COLOR=1` removes ANSI color without changing the content.

Usage tables fit the terminal width. When the full table is too wide, the renderer steps down in this order until it fits: abbreviate token counts (`616M`, `24.3K`; cost stays exact), hide Reasoning and Cache Write, hide Models, then hide Input and Output. At any step, a model name longer than the space left for the Models column (at least 20 characters) gets a middle `…` instead of wrapping. Period, Source, Cache Read, Total, and Cost always stay (Cost unless `--no-cost`). A note on `stderr` lists what was left out. Piped output has no terminal width and keeps every column.

```bash
llm-usage daily --compact
```

`--compact` starts from the abbreviated table without Reasoning and Cache Write, even when the terminal is wide or the output is piped. It works with terminal and Markdown output, not JSON. If even the narrowest table is wider than the terminal, as on a phone, each row is listed on its own instead: a title line with the period and source, then one `label value` line each for Input, Output, Cache Read, Total, and Cost (abbreviated; Models, Reasoning, and Cache Write are left out). The other terminal reports (summary, session, compare, efficiency, optimize, wrapped) switch to the same list when their table does not fit, and a report title too wide for its box prints without one. `--per-model-columns` tables keep the table and warn on `stderr` instead, since their metric lines only make sense next to the model names.

```bash
llm-usage daily --no-cost
llm-usage monthly --share --no-cost
```

`--no-cost` leaves cost out of `daily`, `weekly`, and `monthly` for a screenshot or a shared report that should not show spend: tables drop the Cost column, and the share report holds no cost at all. It works with terminal, Markdown, and `--share`, not JSON.

## JSON

```bash
llm-usage daily --all --json > usage.json
```

Use JSON for scripts and pipelines. Without date bounds, `daily` and `weekly` cover only their default windows (the last 7 days and the last 8 weeks), so scripts that need full history should pass `--all` or explicit `--since`/`--until` dates. Every report wraps its payload in a versioned envelope:

```json
{
  "schemaVersion": 1,
  "report": "usage",
  "data": []
}
```

`report` identifies the report family (`summary`, `usage`, `session`, `trends`, `compare`, `efficiency`, `optimize`, `wrapped`, `doctor`, or `prune`) and `data` carries the report-specific payload documented on each report page. `schemaVersion` increments only on breaking JSON changes; additive fields inside `data` are safe and do not bump it. Diagnostics never enter the JSON body. The envelope arrived in 0.8.0 — [Migrating to 0.8](/llm-usage-metrics/migrating-to-0-8/) maps the old field names to the new ones.

Every payload has a published JSON Schema (draft 2020-12) validated in CI against real CLI output:

| ------------------ | ---------------------------------------------------------------------------------------------------------------- |

| usage              | [report-usage.v1.schema.json](https://ayagmar.github.io/llm-usage-metrics/report-usage.v1.schema.json)           |

| compare            | [report-compare.v1.schema.json](https://ayagmar.github.io/llm-usage-metrics/report-compare.v1.schema.json)       |
| efficiency         | [report-efficiency.v1.schema.json](https://ayagmar.github.io/llm-usage-metrics/report-efficiency.v1.schema.json) |
| optimize           | [report-optimize.v1.schema.json](https://ayagmar.github.io/llm-usage-metrics/report-optimize.v1.schema.json)     |

The installed CLI also carries these schemas, so pipelines can validate against the exact contract of their installed version without the network:

```bash
llm-usage schema usage > report-usage.schema.json
llm-usage schema --list
```

`schema` accepts every report name plus `events-line`, `machine-export` and `config`, and prints the schema document itself (not wrapped in the report envelope). Report, `events-line` and `machine-export` schemas embed the shared definitions under `$defs`, so the printed file compiles on its own in any JSON Schema 2020-12 validator.

## Machine export

```bash
llm-usage machine export > usage.ndjson
```

`machine export` prints the events this machine's reports count, so another machine can combine them into its own reports. It refreshes the local event store the way a report does and needs it enabled. The output is NDJSON with one object per line, each validated by [machine-export.v1.schema.json](https://ayagmar.github.io/llm-usage-metrics/machine-export.v1.schema.json):

- a `header` line with the bundle `format`, its `version` (1), the exporting CLI version and host name, and `parserVersions`, the parser version each source was read with (missing from exports before it was added). Version 1 headers can gain fields, so readers should ignore header fields they do not know
- a `file` line per counted file, with its `source`, `filePath`, an opaque `revision` and its `events` (the same objects as `events --format jsonl`, but unpriced: `costUsd` is present only when the source recorded the cost)
- an `end` line listing every counted file as `[source, filePath, revision]`, plus the total `eventCount`

A bundle without its `end` line is incomplete. `--known <path>` (or `-` for stdin) takes `{"version":1,"files":[[source, filePath, revision], ...]}`, usually the `files` of a previous `end` line, and leaves out the events of files listed at the same revision. A file that a reader holds but the `end` line no longer lists is no longer counted.

## Markdown

```bash
llm-usage daily --markdown > usage.md
```

Markdown works for summary, usage, compare, session, efficiency, optimize, trends, and wrapped reports. It does not work for doctor, prune, or events.

Usage and session output keep the same ordering and row limits as the terminal renderer. `--per-model-columns` and `--compact` also work with Markdown usage reports.

## Share reports

`--share` writes one self-contained HTML report to the current directory and still prints the normal report to `stdout`. The file holds the command's usage by hour, source, model, project, and machine, so the page can:

- chart cost and tokens over time, stacked by source, model, project, or machine, plus model mix, cache hit rate, cost per active hour, 5-hour blocks, and an hour-by-weekday heatmap
- narrow the period, switch between hour, day, week, and month, filter by source, model, project, and machine, and switch the cost mode
- list projects and their sessions in sortable tables
- export each chart as PNG or SVG, copy it as an image, and save the current view as a new file

The page opens in your default browser; add `--no-open` to only write the file (useful over SSH or in scripts). It works offline: it loads nothing from the network and needs no extra software. Copying an image needs a browser that supports image clipboard writes; the PNG download works everywhere.

| Report     | Command                                                        | File                            | Opens on                            |
| ---------- | -------------------------------------------------------------- | ------------------------------- | ----------------------------------- |
| Summary    | `llm-usage summary --share`                                    | `summary-share.html`            | The past 53 weeks                   |
| Usage      | `llm-usage monthly --share`                                    | `usage-monthly-share.html`      | The report's window                 |
| Compare    | `llm-usage compare --share`                                    | `compare-share.html`            | The current window                  |
| Trends     | `llm-usage trends --share`                                     | `trends-share.html`             | The report's date range             |
| Wrapped    | `llm-usage wrapped --year 2026 --share`                        | `llm-usage-wrapped-2026.html`   | The year, under its recap           |
| Efficiency | `llm-usage efficiency monthly --share`                         | `efficiency-monthly-share.html` | The report's window, with its panel |
| Optimize   | `llm-usage optimize monthly --candidate-model gpt-4.1 --share` | `optimize-monthly-share.html`   | The report's window, with its panel |

Daily and weekly usage write `usage-daily-share.html` and `usage-weekly-share.html`; efficiency and optimize name the file after their granularity the same way. A compare file holds both windows and opens on the current one.

Project names come from repository folder names, never full paths. `--redact` replaces them with `project-1`, `project-2`, … and machine names with `machine-1`, … (`local` stays). The page's **Hide names** toggle masks names on screen and in exports without changing the file. Session IDs are never written.

Without `--no-cost`, the file holds explicit, estimated, and combined costs so the page can switch between them. That loads the pricing data even when the command runs with `--cost-mode explicit`: from the price cache, or downloaded when the cache is cold, unless you pass `--pricing-offline`. If the prices do not load, the file keeps logged costs only and a warning on `stderr` says so. When a long history would make the file larger than about 8 MB, usage older than 90 days before the end of the window is kept by day instead of by hour, and the page says from which date hourly detail starts.

Session, doctor, prune, and events do not support `--share`.

## Per-model columns

```bash
llm-usage monthly --per-model-columns
llm-usage monthly --markdown --per-model-columns
```

This usage-report option expands token and cost values per model into aligned multiline cells. Models are ranked by total tokens inside each row.

## Keep diagnostics separate

```bash
llm-usage daily --all --json > usage.json 2> usage.log
```

`usage.json` contains report data. `usage.log` contains a one-line discovery and pricing summary, any warnings, and notes such as `--history` totals. Pass `--quiet` to keep only warnings, or `--verbose` to add per-source counts, routine skipped rows, and the config and env blocks.
