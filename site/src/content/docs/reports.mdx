Start with a question, then narrow the result with source, model, provider, project, or date filters. If you have not run the CLI yet, follow [Getting Started](/llm-usage-metrics/getting-started/).

## Tokens and cost over time

| Question                                                            | Command                                      | Default window                  |
| ------------------------------------------------------------------- | -------------------------------------------- | ------------------------------- |
| [What did I spend today and this month?](/llm-usage-metrics/usage/) | `llm-usage`                                  | Today, 7 days, month to date    |
| [Which hours were busy today?](/llm-usage-metrics/usage/)           | `llm-usage hourly`                           | Today                           |
| [How much did I use each day?](/llm-usage-metrics/usage/)           | `llm-usage daily`                            | Last 7 days                     |
| [How did the weeks or months add up?](/llm-usage-metrics/usage/)    | `llm-usage weekly` or `llm-usage monthly`    | Last 8 weeks, or full history   |
| [What changed from last month?](/llm-usage-metrics/compare/)        | `llm-usage compare`                          | Month to date vs. the same days |
| [Is usage rising or falling?](/llm-usage-metrics/trends/)           | `llm-usage trends --metric tokens --last 14` | Last 30 days                    |
| [What did the year look like?](/llm-usage-metrics/wrapped/)         | `llm-usage wrapped`                          | The current year                |

`--last N` reports the last N periods of the command, counting the current one, and `--all` reports full history where the default is a recent window. Each question links to the guide for its command, which lists the limits.

```bash
# Limit the report to one source and one calendar month
llm-usage monthly --source codex --since 2026-09-01 --until 2026-09-30
```

:::note[Estimated cost is not your invoice]
The CLI preserves source-recorded cost and estimates other costs from available pricing. A tilde marks partial cost; a dash means no resolved cost. Subscription billing, discounts, and missing source data can make these values differ from your actual bill. See [Pricing](/llm-usage-metrics/pricing/).
:::

## Projects and sessions

| Question                                                                           | Command                        | Default window |
| ---------------------------------------------------------------------------------- | ------------------------------ | -------------- |
| [Which projects cost the most?](/llm-usage-metrics/projects/)                      | `llm-usage projects`           | Full history   |
| [Which conversations cost the most?](/llm-usage-metrics/session/)                  | `llm-usage session --top 10`   | Full history   |
| [Which tools do my agents call, and which fail?](/llm-usage-metrics/tools/)        | `llm-usage tools`              | Last 7 days    |
| [How does usage compare with commits in one repo?](/llm-usage-metrics/efficiency/) | `llm-usage efficiency monthly` | Full history   |

Most reports also take `--repo` to count some projects only, and the usage reports split rows by project with `--by-repo`. Efficiency ratios depend on project attribution and Git history; they do not measure code quality or developer productivity.

## Plans and models

| Question                                                                        | Command                                                                  | Default window |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | -------------- |
| [How much of my 5-hour window have I used?](/llm-usage-metrics/blocks/)         | `llm-usage blocks`                                                       | Last 7 days    |
| [Would the API have cost more than my subscription?](/llm-usage-metrics/value/) | `llm-usage value`                                                        | Full history   |
| [What would my usage cost on another model?](/llm-usage-metrics/optimize/)      | `llm-usage optimize monthly --provider openai --candidate-model gpt-4.1` | Full history   |
| [Which price does a model name get?](/llm-usage-metrics/pricing/)               | `llm-usage pricing claude-sonnet-4-5`                                    | Reads no usage |

[Optimize](/llm-usage-metrics/optimize/) prices your observed token mix against candidate models. It does not run the models or predict their output quality, latency, or future token usage.

## Exports, sharing, and automation

| Need                              | Command                           | Guide                                                     |
| --------------------------------- | --------------------------------- | --------------------------------------------------------- |
| An interactive HTML report        | `llm-usage monthly --share`       | [Interactive report](/llm-usage-metrics/share/)           |
| An aggregated report for a script | `llm-usage daily --json`          | [Output formats](/llm-usage-metrics/output-formats/)      |
| A table for a document            | `llm-usage daily --markdown`      | [Output formats](/llm-usage-metrics/output-formats/)      |
| Individual normalized events      | `llm-usage events --format jsonl` | [Events export](/llm-usage-metrics/events/)               |
| Events for a spreadsheet          | `llm-usage events --format csv`   | [Events export](/llm-usage-metrics/events/)               |
| A line for a status bar           | `llm-usage statusline`            | [Status line](/llm-usage-metrics/statusline/)             |
| The installed report's schema     | `llm-usage schema usage`          | [JSON contracts](/llm-usage-metrics/output-formats/#json) |

Report JSON uses a versioned envelope. Event JSONL is one event per line without that envelope. Diagnostics go to `stderr`, so you can redirect report data safely. [Output formats](/llm-usage-metrics/output-formats/#choose-a-format) lists which formats each command supports.

## Discovery and maintenance

```bash
# Inspect source locations and ledger health
llm-usage doctor

# Show which config-file values are active
llm-usage config show

# Preview removal of departed files suppressed as moves or duplicates
llm-usage prune --suppressed
```

Use [Doctor](/llm-usage-metrics/doctor/) when data is missing, [Configuration](/llm-usage-metrics/configuration/) to save defaults, and [Caching and history](/llm-usage-metrics/caching/) to understand the event ledger. `prune` is a dry run unless you pass `--apply`; applying age-based pruning permanently removes selected retained history.
