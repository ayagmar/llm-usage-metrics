`llm-usage session` lists usage per conversation (session) rather than per calendar period, so you can find your most expensive or most active sessions and where they ran.

## Command structure

```text
llm-usage session [options]
```

Examples:

```bash
llm-usage session
llm-usage session --top 50
llm-usage session --top 0
llm-usage session --id 486c3261
llm-usage session --id 486c3261 --timeline
llm-usage session --by-repo
llm-usage session --source codex --json
llm-usage session --markdown
```

## Options

- `--top <n>`: how many rows to show, ranked by cost (default 20; `--top 0` shows all)
- `--id <session-id>`: keep only sessions whose id contains the value (case-insensitive; repeatable or comma-separated); cannot be combined with `--by-repo`
- `--by-repo`: aggregate sessions into one row per [project](/llm-usage-metrics/projects/)
- `--timeline`: with `--id` naming one session, list that session request by request (see [Timeline](#timeline)); cannot be combined with `--top`
- `--repo <project>`: count only some projects, as described on [Projects](/llm-usage-metrics/projects/#narrow-the-scope)
- shared filters apply: `--source`, `--provider`, `--model`, `--machine`, `--since`, `--until`, `--timezone`, source-path overrides, pricing flags, and `--no-history`

Without date flags, `session` covers your full history. It supports terminal, `--json`, and `--markdown` output, but not `--share`; the [interactive report](/llm-usage-metrics/share/) lists each project's sessions without their ids.

## Output

The terminal report is a boxed **Session Usage Report** table with `Session`, `Source`, `Project`, `Last Activity`, `Duration`, `Total`, `Cost`, and `Models` columns, sorted by cost. `Project` uses the same labels as `llm-usage projects`: the repository's folder name, with parent folders added when two repositories share it, and `(unattributed)` for sessions without one. `Duration` is the raw span from a session's first to last event (`-` for single-event sessions). Sessions have no `TOTAL` row because each row is a conversation, not a calendar period. When the list is truncated, a note is printed on `stderr`:

```text
Showing top 20 of 1653 sessions by cost. Use --top 0 for all.
```

`--by-repo` replaces the per-session rows with one row per project, the working directory the tool recorded (`Project`, `Sessions`, `Last Activity`, `Total`, `Cost`, `Sources`). Sessions without a recorded directory are grouped under `(unattributed)`.

## Timeline

`--id <session-id> --timeline` shows one session in time order: each request with its time of day (the date heads the table, and a row on a later day shows its date), model, input, cache read, cache write and output tokens, its cost, and the running total of the session's cost so far. It answers "why did this session cost $12": the running total shows where the cost climbed, and the requests around it show what the model was doing.

The `--id` value must match exactly one session in the window. When it matches several, the error lists up to 10 of them with their source and last-activity date, so you can pass more of the id:

```text
--timeline needs exactly one session, but --id 486c matches 2:
  codex   486c3261-d87e-4971-8813-904c9e5a9009  2026-03-05
  claude  486c77aa-0f12-4c55-9a1e-6b2d0e3f4a10  2026-02-11
Pass more of the session id to --id.
```

Requests come from the same data as every other report, history included. Between them, the timeline shows the session's tool calls and its user and assistant turns, read from the session file when it is still on disk (Claude Code, Codex and pi log them; other sources show requests only). A departed file or another machine's session has no tool calls or turns; a note on `stderr` says so. The terminal and Markdown tables fold everything between two requests into one line, such as `1 user turn · 12 tool calls: Bash ×7, Read ×5, 1 error`. No rows are cut: a long session prints every request.

## JSON shape

Default `--json` returns an array of session rows under `data`:

```json
{
  "schemaVersion": 1,
  "report": "session",
  "data": [
    {
      "rowType": "session",
      "source": "codex",
      "sessionId": "486c3261-d87e-4971-8813-904c9e5a9009",
      "repoRoot": "/path/to/repo",
      "firstActivity": "2026-03-05T10:00:00.000Z",
      "lastActivity": "2026-03-05T11:30:00.000Z",
      "durationMs": 5400000,
      "activeMs": 2700000,
      "eventCount": 42,
      "models": ["gpt-5.1"],
      "inputTokens": 120000,
      "outputTokens": 8000,
      "reasoningTokens": 0,
      "cacheReadTokens": 40000,
      "cacheWriteTokens": 0,
      "totalTokens": 168000,
      "costUsd": 1.23
    }
  ]
}
```

`durationMs` is the raw span: `lastActivity` minus `firstActivity`; it over-counts idle time by design. `activeMs` estimates activity from event timing: the sum of inter-event gaps, each capped at 5 minutes, so a session left open overnight contributes at most 5 idle minutes per gap. Single-event sessions get `activeMs: 0`. This is an event-gap estimate, not a measurement of human working time.

`repoRoot` is omitted when the session has no project.

`--by-repo --json` returns an array of repo rows (`rowType: "repo"`, `repoRoot`, `sessionCount`, `firstActivity`, `lastActivity`, `sources`, and the same token and cost totals). The `(unattributed)` row has no `repoRoot`. `--timeline --json` returns an object under `data`: `session`, the matched session row, and `rows` in time order. Each row has a `kind`: `usage` rows carry `timestamp`, `model`, the token buckets, `costUsd`, `runningCostUsd`, and `runningCostIncomplete` when this or an earlier request has no price; `tool_call` rows carry `timestamp`, `name` and `status` (`ok`, `error`, or `unknown` when the file has no result); `message` rows carry `timestamp` and `role`, never the text. JSON rows are not folded.

The full contract is [report-session.v1.schema.json](https://ayagmar.github.io/llm-usage-metrics/report-session.v1.schema.json).
