## Default location

- `~/.codex/sessions/**/*.jsonl` (or `$CODEX_HOME/sessions/**/*.jsonl` when `CODEX_HOME` is set)

## Override

```bash
llm-usage daily --codex-dir /path/to/codex/sessions
# or
llm-usage daily --source-dir codex=/path/to/codex/sessions
# several directories (repeat the flag)
llm-usage daily --codex-dir /path/one/sessions --codex-dir /path/two/sessions
```

## Parsing notes

The adapter handles Codex token-count events and computes deterministic usage deltas for cumulative counters. Newer Codex releases also write one `token_usage_record` row per API response; the adapter emits the records collected before each `token_count` row (deduplicated by `response_id`) in place of that row's delta, and a `token_count` with no records before it still emits its delta. This recovers the response that triggers an auto-compaction (the cumulative counters never include it) and maps `cache_write_input_tokens`.

A forked session (`/fork`, a fork from the session picker, or a forked subagent) starts with its own `session_meta`, which names `forked_from_id`, followed by a copy of the parent's lines stamped with the time of the fork. Codex 0.152 and later end the copy with a `thread_settings_applied` event carrying the fork's id. The adapter emits nothing from the copied lines (no usage, messages or tool calls) and counts the fork's own turns from the parent's last running total, so a parent and its fork add up to the parent plus the fork's own turns. A fork that references the parent's history instead of copying it (`history_mode: paginated`) has no copied running total. From Codex 0.153, which logs a `token_usage_record` for every response, a `token_count` written before the fork's first response (a usage limit, a full context window, a compaction) is taken as the parent's running total, not new usage. A 0.152 fork of that kind gives no such signal, so it still counts the parent's last response once in that case. Forks written by Codex 0.88 to 0.151, and 0.152 forks whose closing event lacks the fork's id, do not mark where the copy ends. For those the adapter reads the parent rollout, found by the `forked_from_id` in its file name under the same sessions directory, and ends the copy at the last `token_count` whose running total matches the parent's, in order. Codex starts the fork from that total, so the fork's own turns never match it. Usage is then exact. Lines copied after that `token_count`, such as an interrupted turn's last tool output, count as the fork's messages and tool calls. In a fork from an earlier message whose parent went on, a rate-limit `token_count` that opens both the parent's next turn and the fork's first turn repeats the same total, so the fork's lines before it (its first user message) are taken as copied. A change to the parent re-parses the fork. When the parent is missing, the copied lines count again on the day of the fork, as before.

The project (`repoRoot`) comes from the `cwd` of the latest `session_meta` or `turn_context` row, and the provider from `session_meta`'s `model_provider` (`openai` when it is not logged).
