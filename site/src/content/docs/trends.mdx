`trends` shows daily movement over time instead of a tabular aggregate.

```text
llm-usage trends [options]
```

<TerminalShot src={termTrends} label="llm-usage trends output" alt="Terminal output of llm-usage trends: a bar chart of daily cost over the last 30 days, with the total, the daily average, and the peak day underneath" />

## Examples

```bash
# Default: last 30 local calendar days of cost
llm-usage trends

# Last 7 days of token usage
llm-usage trends --metric tokens --last 7

# Combined date window
llm-usage trends --since 2026-02-01 --until 2026-02-28

# Per-source JSON output
llm-usage trends --by-source --json

# One row per project
llm-usage trends --by-repo --metric active-hours

# Write an interactive HTML report of the last 14 days
llm-usage trends --last 14 --share
```

## Options

- `--last <n>`: chart the last n local calendar days, counting today
- `--all`: chart every day from the first day with usage through today; not with `--last`, `--since` or `--until`
- `--metric <name>`: `cost` (default), `tokens`, or `active-hours`
- `--by-source`: render one sparkline row per source
- `--by-repo`: render one sparkline row per [project](/llm-usage-metrics/projects/); cannot be combined with `--by-source`
- `--share`: write an [interactive report](/llm-usage-metrics/share/) `trends-share.html` of the date range
- shared filters apply: `--source`, `--provider`, `--model`, `--repo`, `--machine`, `--since`, `--until`, `--timezone`, source-path overrides, pricing flags, and `--no-history`

`trends` supports terminal output, `--json`, `--markdown` (one row per date plus a Total row), and `--share`. In the share report you can split the charts by source, model, project, or machine, whatever the command's flags.

## `--last` vs `--since` / `--until`

- If you pass `--last <n>`, the range is `today - (n - 1)` through local today.
- If you pass neither `--last` nor explicit date flags, the command defaults to the last 30 local calendar days.
- `--last` cannot be combined with `--since`, `--until` or `--all`, and `--all` cannot be combined with dates.
- `--until` without `--since` expands back to the earliest observed day after filtering.

In terminal output, chart labels, the peak, and the spike list name days as `Mar 06`, or as `2025-03-06` when the range crosses a year; Markdown always uses `2025-03-06`. A short range on a wide terminal draws each day up to 4 columns wide.

## Metric semantics

### `--metric cost`

- Reuses the same pricing pipeline as usage reports.
- Incomplete pricing is carried into the trend output.
- Approximate totals and peaks use the existing `~` convention.
- Marks spend spikes: days that cost at least $1 and at least 3 times the median cost of the active days among the 28 days before them. A day with fewer than 3 active days before it is never a spike. The terminal and Markdown output list the 5 costliest under the totals, in date order, and count the rest (`+9 more`); JSON sets `spike: true` on those days in `totalSeries`. To check the first days of the chart, `trends` also reads the 28 days before it.

### `--metric tokens`

- Uses daily `totalTokens`.
- Skips pricing loads entirely.
- Pricing flags are accepted but have no effect in this mode.

### `--metric active-hours`

- Charts per-day active time: each day's events are grouped by session, gaps between consecutive events are capped at 5 minutes, and time where sessions overlap counts once, so a day never exceeds 24h. The total is wall-clock time, matching `wrapped`'s `Hours`; with `--by-source` or `--by-repo`, each series takes the union of its own sessions, so when sources or projects ran in parallel the series can add up to more than the total.
- A session crossing midnight splits at the day boundary: each day counts only the gaps between that day's events.
- Terminal and Markdown output format durations (`2h 14m`); JSON `value`, `total`, `average`, and `peak.value` are **milliseconds**, matching session `activeMs`.
- Skips pricing loads entirely, like `tokens`.

## `--by-source`

`--by-source` renders one sparkline row per source instead of a single combined chart.

- terminal rows and Markdown columns are ordered by total, highest first; JSON `sourceSeries` keeps the adapter/source order
- missing days are zero-filled
- sources with no observed data in the selected range are omitted

## `--by-repo`

`--by-repo` renders one sparkline row per project, ordered by total, with the same zero-filled days as `--by-source`. JSON carries the rows under `projectSeries`, each with `repoRoot` (`null` for `(unattributed)`), `project`, `buckets`, and `summary`.

With `--metric active-hours`, a session that moves between projects splits into runs at each switch. Each run counts its own capped gaps for its project; the gap across a switch counts for neither, and a return to a project starts a new run. The projects therefore never add up to more than the combined active time.

## Reading approximate cost output

When any bucket in the selected range has incomplete pricing:

- the affected series summary is marked approximate with `~`
- JSON includes `incomplete: true` on affected buckets and summaries

If no observed bucket in the selected range has resolved cost, the terminal output adds a note suggesting `--metric tokens` or working pricing.

## JSON shape

```json
{
  "schemaVersion": 1,
  "report": "trends",
  "data": {
    "metric": "cost",
    "dateRange": { "from": "2026-02-06", "to": "2026-03-06" },
    "totalSeries": {
      "source": "combined",
      "buckets": [
        { "date": "2026-02-06", "value": 1.57, "observed": true },
        { "date": "2026-02-07", "value": 0, "observed": false }
      ],
      "summary": {
        "total": 87.4,
        "average": 2.91,
        "peak": { "date": "2026-02-28", "value": 5.12 },
        "incomplete": true,
        "observedDayCount": 12
      }
    }
  }
}
```

Diagnostics are never included in the JSON body; they remain on `stderr`.
